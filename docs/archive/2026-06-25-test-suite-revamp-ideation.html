Ideation: Test Suite Revamp

date: 2026-06-25 topic: test-suite-revamp focus: more robust & easily runnable mode: repo-grounded

Grounding Context

Codebase Context. Harness lives in deepagent-image/project/; tests in project/tests/.

  • Surface: 2 files — test_cost.py (~39 tests), test_sync_models.py (~16 tests). All pure-math, no network / no API keys; run on a bare interpreter.
  • Duplicated bootstrap: identical hand-rolled _load() import shim in both (test_cost.py:26-35 ≡ test_sync_models.py:18-27), built to dodge harness/__init__.py:16 (from harness.cli import main → pulls dotenv/langgraph/deepagents).
  • Duplicated runner: hand-rolled __main__ loop in each file (bare except Exception, repr(exc) — no assert introspection).
  • Run path: smoke.{ps1,sh} hardcode each test filename (smoke.ps1:11,13) and run inside Docker; comment notes "no pytest dependency is needed" — requirements.txt ships no pytest.
  • Coverage gaps: providers.py routing, loaders.py, hooks.py, cli.py/run_repl, agent.py untested.
  • No CI: no .github/ — nothing runs tests despite the CLAUDE.md-mandated branch+PR flow.

Topic Axes

  1. Test runner & discovery
  2. Shared test infrastructure
  3. Coverage breadth
  4. CI / automation
  5. Failure diagnostics & determinism

Ranked Ideas

  1. Adopt pytest as the one canonical runner
  2. Two-tier CI on every PR
  3. Single shared test-infra module (conftest + fixtures)
  4. Cover the untested core: model routing first
  5. Import-isolation guard test
  6. Coverage measurement with a floor
  7. Root-cause: make harness import side-effect-free

R1. Adopt pytest as the one canonical runner

axis: runner & discovery confidence: 85% complexity: Medium
Description Make pytest tests/ the single way to run tests everywhere. Add a pyproject.toml/pytest.ini with testpaths, replace the two hardcoded filenames in smoke.{ps1,sh} with a directory run, retire the per-file hand-rolled __main__ runners, and parametrize the table-driven cost cases so each row reports independently.
Basis — direct Files are already pytest-shaped (test_* functions, plain assert). smoke.ps1:11,13 and smoke.sh:11-12 name each file literally; both the .ps1 and .sh twin must change to add one test file.
Rationale "Easily runnable" hinges on one obvious command. Discovery removes the 2-script edit tax (and the silent-skip risk it creates), and pytest's assert rewriting turns repr(exc) into a real diff on failure.
Downsides The in-image path currently runs dependency-free on purpose (smoke.sh:9; requirements.txt has no pytest). Going pytest-canonical means adding pytest to the image — or splitting: pytest on the host, keep the standalone runners only for the sealed container. Decide that explicitly rather than by accident.

R2. Two-tier CI on every PR

axis: CI / automation confidence: 90% complexity: Low
Description Add a GitHub Actions workflow. Tier 1: a fast keyless job that runs the pure-math tests on a plain Python (seconds, no Docker, no secrets) — gates every PR. Tier 2: a slower job that builds the image and runs smoke.sh end-to-end, catching import-cycle / package-split breaks.
Basis — direct No .github/ exists. Root CLAUDE.md mandates a branch+PR-per-session workflow, yet nothing runs the tests on those PRs. The tests need no keys/network (test_cost.py:1-10), so tier 1 is trivially CI-able.
Rationale A mandated PR flow with no automated gate means "robust" depends on every human remembering to run smoke locally. CI makes the green check the contract. Highest leverage-per-effort here.
Downsides Tier 2 spends CI minutes on a Docker build; keep it required-but-parallel, or PR-only, to avoid slowing the fast signal.

R3. Single shared test-infra module (conftest + fixtures)

axis: shared infrastructure confidence: 88% complexity: Low
Description Lift the duplicated _load() bootstrap into one place — a tests/conftest.py or shared helper — so both files import it instead of copying it. Fold in registry isolation: a fixture that points DEEPAGENTS_PROVIDERS_DIR at a checked-in fixture registry, so pricing tests don't depend on whatever rates happen to be committed.
Basis — direct test_cost.py:26-35 and test_sync_models.py:18-27 are byte-for-byte the same _load(). test_providers_load_pricing_from_registry asserts against the live registry ("after we fill TOMLs", test_cost.py:362); CLAUDE.md already notes DEEPAGENTS_PROVIDERS_DIR exists "used by tests" but the test doesn't use it.
Rationale Two copies of the import shim drift the moment one is touched. One source removes that class of bug; fixture isolation makes the pricing test deterministic instead of coupled to committed data.
Downsides A conftest.py only auto-loads under pytest — if the standalone runners survive (see R1 downside), the shared helper must be a plain importable module they can use too.

R4. Cover the untested core: model routing first

axis: coverage breadth confidence: 82% complexity: Medium
Description Add tests for the routing logic that decisions actually flow through: choose_model ascending-priority scan, the "skip provider whose default_model is unset" rule, DEEPAGENTS_MODEL=provider:model override, and the OpenAI-compatible *_BASE_URL requirement. Then the cheaper wins: loaders.py optional-file IO and parse_args / single-turn degradation.
Basis — direct CLAUDE.md (model-routing section) describes priority scan, default-model skip, and base-URL rules as load-bearing — yet tests touch providers.py only via one pricing assertion (test_cost.py:359-371). The branchy selection logic is unverified.
Rationale "More robust" most literally means covering the logic that picks a model and validates creds — today a routing regression ships green. The cost math is already well-covered; this is where the real exposure is.
Downsides Routing tests need registry fixtures and may brush credential-validation paths — pairs naturally with R3's fixture isolation; sequence it after R3.

R5. Import-isolation guard test

axis: diagnostics & determinism confidence: 78% complexity: Low
Description A small test that asserts the two contracts the codebase relies on but never checks: importing harness.cost pulls in neither langgraph/deepagents nor providers (the "cost.py holds math only, never imports providers" rule), so it stays runnable on a bare interpreter and the providers→cost direction can't reverse.
Basis — direct smoke.sh:7 exists precisely to catch a "providers↔cost import cycle"; CLAUDE.md §2.4 states cost.py "must never import providers.py". Both are enforced today only by a manual smoke import, not a test that names the rule.
Rationale The whole bootstrap hack and the keyless-test property depend on this staying true. A guard test turns an implicit invariant into a named failure with a clear message the day someone adds the wrong import — cheap insurance on a load-bearing assumption.
Downsides Import-graph assertions can be fiddly (must check sys.modules in a clean subprocess to be honest); keep it tight or it gives false confidence.

R6. Coverage measurement with a floor

axis: coverage breadth confidence: 70% complexity: Low
Description Wire pytest-cov (or coverage.py) into the test run and surface the number — in CI output and optionally as a soft floor that fails if it drops. Makes "which modules are untested" a measured fact instead of a guess.
Basis — reasoned R4 names today's gaps from reading the tree by hand; that doesn't scale as the harness grows. A coverage number is the instrument that keeps the gap list honest without re-auditing manually each time, and it makes R4's progress visible.
Rationale Robustness you can't measure regresses quietly. A visible percentage (even informational at first) converts coverage from opinion into a tracked signal — and pairs with R2 to show it on every PR.
Downsides A hard floor invites gaming (tests that execute lines without asserting); start informational, and note the in-image dependency-free constraint — coverage tooling lives on the host/CI side, not the sealed runtime.

R7. Root-cause: make harness import side-effect-free

axis: shared infrastructure confidence: 65% complexity: Medium–High
Description Remove the eager from harness.cli import main at package import so that import harness.cost doesn't drag in dotenv/langgraph/deepagents. With the side effect gone, the entire _load() bootstrap hack can be deleted and tests import modules normally.
Basis — direct harness/__init__.py:16 is from harness.cli import main; the test files' own comments (test_cost.py:19-24) cite exactly this as why they bypass the package. Make entry lazy (e.g. a main() that imports cli inside the function, or rely on __main__.py) and the cause disappears.
Rationale R3 deduplicates the workaround; this deletes the reason it exists. Cleaner imports also make every future test (R4) trivial to write — no shim to copy. Highest leverage on the bootstrap problem.
Downsides Touches harness runtime, not just tests — must confirm python3 main.py, python3 -m harness, and the REPL entry all still resolve main. Higher blast radius; do it behind R2's CI net, not before it.
